## 1. 四套历史记录中位置为何均无效

| 结论 | 确定程度 | 证据 |
|---|---|---|
| 当前代码的“位置无效”由输入有效位决定：数据端把 `AdsFastSnapshot.position_valid` 原样写入 `MotionCsvRow.position_valid`，该标志为假时位置列规范化为 `NaN`。这证明当前赋值语义；不能单凭当前代码排除历史版本缺陷。 | 已确认 | `介入机器人/B数据端/工程/ADS项目/main.cpp:4651-4658`；`介入机器人/B数据端/工程/ADS项目/experiment_recorder.cpp:238-248` |
| `position_valid` 只要求 ADS 快照位置、初始化/左限位和四个线性速度有限，并不要求 `control_active` 为真。因此“未处于控制状态导致位置无效”与当前代码语义不符。 | 已确认 | `介入机器人/B数据端/工程/ADS项目/ads_communication.cpp:1479-1513`；`介入机器人/B数据端/工程/ADS项目/main.cpp:1062-1066` |
| 连接未进入完整 `Running` 的拍会发布无效快照；连接初始化失败时也发布全零默认快照后 `continue`。这可以解释无效位置行，但不能从历史 CSV 单独证明是哪一种路径发生。 | 已确认 | `介入机器人/B数据端/工程/ADS项目/ads_communication.cpp:847-860`、`介入机器人/B数据端/工程/ADS项目/ads_communication.cpp:985-995` |
| 当前记录器有“有效 ADS 读但不在控制”仍记录有效位置的能力；四套历史文件位置全无效，说明这些记录期间没有拿到被判定为有效的运动快照，或文件来自不同/更早版本。仅凭文件不能区分连接状态、非有限位置/速度、PLC 状态或旧版本。 | 推断 | 当前代码与历史文件的字段含义见上述行；`介入机器人/B数据端/工程/ADS项目/x64/Release/records/20261102/165217_auto/motion.csv:1`、`介入机器人/B数据端/工程/ADS项目/records/20261108/092851_auto/motion.csv:1`、`介入机器人/B数据端/工程/ADS项目/records/20261108/120537_auto/motion.csv:1`、`介入机器人/B数据端/工程/ADS项目/records/20261110/084418_auto/motion.csv:1`；第一轮统计 `docs/arch_survey_r1/scratch/existing_records_stats.json:1` |
| 前三套记录的 `qpc_anchor/qpc_frequency` 与已有 ADS diagnostic 的 CONNECT 失败时间段相近，且错误码为 local 6、fallback 1861、timeout 1000ms；这支持“当时未进入有效 Running，因而产生无效运动快照”的解释，但不是逐行关联证明。 | 推断 | qpc元数据：`x64/Release/records/20261102/165217_auto/session.json:7`、`records/20261108/092851_auto/session.json:7`、`records/20261108/120537_auto/session.json:7`；对应诊断：`x64/Release/ads_fault_diagnostics.log:1`、`x64/Debug/ads_fault_diagnostics.log:9,4686`；诊断没有 session ID |
| 现有 `session.json` 的 `utc_end=null`、`stop_reason=null`、ADS metrics 全为 null，不能证明记录器在停止时正常写完 final JSON，也不能用这些 null 反推位置原因。 | 已确认 | 例如 `介入机器人/B数据端/工程/ADS项目/records/20261108/092851_auto/session.json:1-37`；final JSON 只有 `stop_async/stop_worker` 路径才写结束字段：`experiment_recorder.cpp:563-619`、`experiment_recorder.cpp:870-1022` |

结论（推断）：四套历史记录的位置无效与“ADS 运动快照无效”这一输入事实相容；当前代码不把“未处于控制状态”当作位置无效原因，已有 CSV 有效/无效行断言也通过（第一轮 `F_测试现状.md` §2.1；现有断言 `介入机器人/B数据端/工程/ADS项目/tools/recording_feedback_test.cpp:63-105`）。但历史 session 未保存源码哈希，确切失效原因仍未知；需要同一会话的 ADS 状态/失败日志、`position_valid` 形成前的四个速度和坐标，及可靠的 final session 文件。

## 3. 记录器主循环开销与阻塞性

| 行为 | 结论 | 证据 |
|---|---|---|
| 启动时自动开启 | 已确认 | `main.cpp:953-960` 调用 `start("auto", ...)`；session 路径由当前工作目录 `records/日期/时间_auto` 生成：`experiment_recorder.cpp:399-447` |
| 每个已排出的 ADS 快照产生一行 force；偶数 attempt sequence 再产生一行 motion | 已确认 | `main.cpp:4612-4650`、`main.cpp:4651-4678`；频率常量 100/50 Hz：`experiment_recorder.cpp:17-18` |
| 控制线程不直接写 CSV；`try_enqueue` 仅做原子队列检查、复制一行和更新 head，队列满则立即丢弃 | 已确认 | `async_csv_writer.h:115-132` |
| 文件打开、格式化、`fprintf`、每 64 行 `fflush` 和错误检测在独立 writer thread | 已确认 | `async_csv_writer.h:12-14`、`async_csv_writer.h:162-204` |
| writer 空队列时固定 `sleep_for(2ms)`；因此正常 enqueue 不等待磁盘，但停止时 `join()` 会等待队列排空/flush；最坏时间受积压、磁盘和 `fflush` 影响，源码未设上限 | 已确认/未知 | 空队列轮询：`async_csv_writer.h:167-176`；排空和 join：`async_csv_writer.h:90-106`；缺少固定上限是源码事实，实际最坏时长未知 |
| 主循环每拍仍执行 `drain_snapshots`、构造行、有限性判断、最近手柄历史线性扫描和 force/motion enqueue，这些是同步 CPU 开销；正常 enqueue 路径没有同步文件 I/O | 已确认 | `main.cpp:4607-4678`；`async_csv_writer.h:115-132` |
| 快照 drain 持 `snapshot_mutex_` 并 `reserve/push_back`；最多从容量2048的队列取记录，每个偶数快照遍历最近100ms手柄历史选择10ms内最近值 | 已确认 | `ads_communication.cpp:19,266-276`；`main.cpp:1472-1483,4610-4612,4659-4675` |
| 每拍 `update_ads_communication_stats` 和可视化 snapshot 会拿 `ads_stats_mutex_`；锁本身未设等待上限 | 已确认 | `main.cpp:4402-4403`；`experiment_recorder.cpp:770-818,826-867` |
| 启动记录仍同步创建目录、打开3文件/写表头并 flush、写 session JSON；UI StartRecording 也在主循环调用 start。故“记录器永不阻塞主循环”不成立 | 已确认 | `experiment_recorder.cpp:457-548`；`async_csv_writer.h:34-87`；`main.cpp:5108` |
| `stop_async` 通常新建停止线程，但若线程创建失败会直接调用 `stop_worker`，同步等待 writer 排空/flush；此前 stop_thread 若仍 joinable 也会 join | 已确认 | `experiment_recorder.cpp:563-619`；`main.cpp:4403,5121` |
| 当前无记录器各段CPU耗时或锁等待的实测，无法给出µs/ms上界；日志的force/motion间隔不能替代该指标 | 未知 | 记录格式见 `experiment_recorder.cpp:20-31`；第一轮 `C_时间敏感动作.md` §C.7.2 |
| 记录器可能间接影响主循环 | 推断 | 队列满时行被丢弃而不阻塞；但每拍构造/扫描和原子操作会消耗预算，实际影响需要带 QPC 主循环测量。现有 CSV 只有文件内间隔，不含主循环起止时间，见第一轮 `C_时间敏感动作.md` §C.7.2 |
