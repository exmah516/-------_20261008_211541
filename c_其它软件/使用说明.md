# DSA 截图发送工具 ScreenCut

本目录是从旧项目复制的独立截图发送程序，运行在能够显示 DSA 影像的 Windows 电脑上。程序名为 `ScreenCut.exe`，窗口标题为“截图传输工具”。它截取桌面的指定矩形区域，将图像压缩为 JPEG，再通过 UDP 直接发送给主端，不经过 ADS 从端。

## 文件

- `ScreenCut/ScreenCut.exe`：旧项目现成的 Release x64 程序，原文件时间为 2024-03-20；本次原样复制。
- `ScreenCut/ScreenCut.exe.config`：运行配置，请与 EXE 放在一起。
- `ScreenCut源码/ScreenCut.sln`：完整独立工程，可用 Visual Studio 打开。
- `文件校验_SHA256.txt`：复制时生成的运行文件和源码校验值。

旧程序来源：

```text
D:\Work_files\Vessel intervention Robot\血管整体项目程序\code\ScreenCut
```

本次没有修改截图代码、通信协议、默认 IP 或截图区域。运行文件为 x64，目标框架是 .NET Framework 4.7.2，程序集引用均为系统框架；不需要海康 SDK、VTK、ADS 或 CAN 驱动。

## 首次连接：先使用第一路

1. 将整个 `ScreenCut` 文件夹复制到显示 DSA 影像的电脑，双击里面的 `ScreenCut.exe`。
2. 打开 DSA 影像窗口，使目标影像在桌面上可见。该工具使用 `CopyFromScreen` 截取屏幕像素，被其他窗口覆盖的部分也会照样截进去。
3. 将工具里的“主端IP”改为主端电脑实际网卡 IP。界面的 `192.168.1.100` 是旧默认值，并不保证是当前主端地址；这里不能填写 ADS 从端 IP，除非它恰好也是接收图像的主端电脑。
4. 在第一行填写截图区域的“左、上、宽、高”。旧默认是 `-1280、0、1280、1024`，对应主屏左侧的一块显示区域。单屏初测可按实际分辨率填写，例如屏幕足够大时使用 `0、0、800、600`。
5. “压缩率”实际上是 JPEG 质量参数，旧默认值为 `40`，合法使用范围为 1～100。先点击“截图测试1”确认预览区域正确。
6. 在主端电脑运行 A 目录的“编译并启动主端.cmd”。确认 DSA 区域没有提示 UDP 端口绑定失败。
7. 在 ScreenCut 中点击第一行的“持续传图”。当前主端可以接收其中的第一行截图（端口 36661、流编号 0）。不要把“持续传图2”当成第二行截图的启动按钮，见下面的真实行为表。
8. 未收到快发控制时，旧程序每 20 个 300 ms 定时周期发送一次，名义约 6 秒一帧；界面线程执行情况也会影响实际间隔。首次等待至少一个慢发周期。
9. 停止发送使用关闭 ScreenCut 窗口；重新设置传图模式时关闭后重新打开。旧界面启动后会禁用两个“持续传图”按钮，没有独立停止按钮。

主端需要允许 ScreenCut 图像使用的 UDP 入站端口 36661；如果使用另一种模式，还涉及 36663。让 Windows 防火墙放行实际使用的应用或端口即可。本次没有修改系统防火墙。

## 旧软件两种传图模式的真实含义

| ScreenCut 按钮 | 发送的截图区域 | 主端图像端口 | 5 字节头的首字节 | ScreenCut 控制监听端口 |
|---|---|---|---|---|
| 持续传图 | 第一行和第二行区域 | 两者都发往 UDP 36661 | 第一行 0，第二行 1 | UDP 36662 |
| 持续传图2 | 第二个发送通道的区域 | UDP 36663 | 0 | UDP 36664 |

每帧先发送 5 字节头：1 字节流编号和 4 字节大端 JPEG 总长度，随后用最多 8192 字节的数据报发送 JPEG 内容。本次原样保留该协议。

当前 A 主端已按旧主端逻辑接收三路：36661 的首字节 0 显示“画面1”，首字节 1 显示“画面2”；36663 显示“心电影像”。主窗口的“画面1/画面2/心电”按钮切换当前显示画面。

## 快发控制与配置

仅接收图像不需要填写 ScreenCut 的 IP；主端要反向发“快发/慢发”控制时，才需要配置它。

在主端电脑将已有的：

```text
A_主端电脑_地址修正版/工程/config/dsa_screencut.ini.example
```

复制为同目录下的 `dsa_screencut.ini`，填写：

```ini
screenCutIp=DSA电脑的实际IPv4地址
listenPort0=36661
listenPort1=36663
commandPort0=36662
commandPort1=36664
maxJpegBytes=67108864
```

`screenCutIp` 必须换成真实数字 IP，不能保留上面的中文占位。修改后重启主端。该 INI 由主端读取，放到 ScreenCut 旁边不会起作用。不要在主端 bin 内再放另一份同名配置，以免遮住工程配置。

旧 ScreenCut 的快发模式名义每 300 ms 一帧，并要求持续收到两字节控制命令。当前主端按旧主端方式每 300 ms 保活发送选中画面的快发命令；点击“DSA慢发”或切换到其他显示区后停止保活，ScreenCut 按旧程序的超时逻辑回到慢发。

当前主端显示组件在 2 秒未收到新帧时显示“过期”并保留最后一帧。因此使用旧程序默认约 6 秒一帧的慢发时，画面在更新间隔内显示“过期”是现有阈值造成的，不一定表示没有收到数据。
