# 影像数据端：截图与海康转发

数据端只运行一个 `ScreenCut/ScreenCut.exe`，同时承担屏幕截图发送和两路海康 TCP 转发。影像主端负责 JPEG 显示、海康登录和视频播放；摄像头转发沿用原模块，不解码或重新压缩视频。

## 启动

1. 关闭旧 ScreenCut。若仍使用旧 ADS，它会占用摄像头端口；停止介入控制后关闭旧 ADS，使用已移除海康转发的新版本。
2. 将整个 `ScreenCut` 目录复制到数据端电脑，保留 EXE、`ImagingCameraRelay.dll`、`ScreenCut.exe.config`。有开发环境时也可双击 `编译并启动数据端.cmd` 构建运行。
3. 检查配置，打开 ScreenCut，摄像头转发随窗口启动。然后打开影像 A 主端。摄像头还没接入时，也能单独测试截图。
4. 关闭 ScreenCut 会同时停止截图和摄像头转发；“停止传图”按钮只停止截图。

编译需要 VS2022（MSBuild、C++ v142、Windows SDK）及 .NET Framework 4.7.2 开发包。只编译而不启动：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build-and-run.ps1 -BuildOnly
```

构建脚本只补齐缺失配置，保留现场修改的地址。

## 截图验证

- 数据端窗口“主端IP”填 `192.168.50.1`。持久默认值在 `ScreenCut.exe.config` 的 `MasterIp` 中，修改配置后重启程序。
- 主端 `A主端/工程/config/dsa_screencut.ini` 的 `screenCutIp` 填 `192.168.50.2`，这是返回快发命令的目标地址。
- 第一组区域先用 `左=0，上=0，宽=640，高=480`，点击“截图测试1”。默认区域现在取实际主屏内的区域，也支持桌面范围内的多屏负坐标。
- 点击第一项“持续传图”，主端选择“DSA影像”。程序立即发送首帧，此后重复截取当前区域，源屏幕变化应同步显示。
- 先传第一路快帧；超过 3 秒未收到有效快发命令，退回约 6 秒一次。主端快发命令正常时，名义间隔约 300 ms。
- 第二组截图随第一项按钮一起发送，沿用旧协议中的画面编号 1；“持续传图2”保留为旧心电端口入口，普通 DSA 测试不用它。

源窗口要保持可见，遮挡内容也会被截入。发送失败会显示具体原因；“已发若干字节”只表示本机发送成功，远端是否收到以主端动态画面为准。

默认截图 UDP 端口：主端接收 `36661`，数据端接收快发命令 `36662`；旧心电入口对应 `36663/36664`。JPEG 长度头和 8192 字节分包格式沿用原程序。

## 摄像头地址

在 `ScreenCut/ScreenCut.exe.config` 修改以下配置后重启，无需改代码：

| 配置项 | 当前值 | 含义 |
| --- | --- | --- |
| `MasterIp` | `192.168.50.1` | 主端地址，也作为摄像头转发允许连接的地址 |
| `RelayListenIp` | `192.168.50.2` | 数据端面向主端的网口 |
| `Camera1Ip` / `Camera1Port` | `192.168.1.64` / `8000` | 第一台摄像头 |
| `Camera1LocalIp` / `Camera1RelayPort` | `192.168.1.96` / `18000` | 数据端相机网口 / 向主端开放端口 |
| `Camera2Ip` / `Camera2Port` | `192.168.1.32` / `8000` | 第二台摄像头，需核实实际地址 |
| `Camera2LocalIp` / `Camera2RelayPort` | `192.168.1.97` / `18001` | 数据端第二相机网口 / 向主端开放端口 |

主端 `A主端/工程/config/hik_cameras.ini` 的 `[camera1]` 为 `192.168.50.2:18000`，`[camera2]` 为 `192.168.50.2:18001`。用户名、密码、通道和码流使用各相机的真实值；数据端转发不保存相机凭据。窗口显示“监听”只说明开始等待连接，最终以主端监控画面为准。

只有一个相机网口时，可用 `.1.96` 依次测试两台：第一台通过“监控1”验证后，保留电脑端网线，更换摄像头端；将 `Camera1Ip` 改为第二台实际地址，重启 ScreenCut 和影像主端，仍通过“监控1”验证。第二台如果需要 PoE，换接后等待供电启动。暂时未接的第二路不会影响第一路或截图。

倍福和相机网口若同处 `.1.0/24`，沿用相机网口较高的跃点数；转发仍固定绑定 `Camera1LocalIp/Camera2LocalIp` 对应网口，不自动修改系统路由。两路同时连接时，须提供实际可用的相机网口；也可让两台接同一交换机，并将两个 LocalIp 都填该网口地址。

## 排查

- 数据端防火墙放行 **ScreenCut.exe** 的 TCP `18000/18001` 和 UDP `36662`；主端放行 UDP `36661`。旧 ADS 的程序规则不会自动授权 ScreenCut。
- 主端执行 `Test-NetConnection 192.168.50.2 -Port 18000` 或 `18001` 只验证转发入口，不能证明已取得摄像头视频。
- 启动转发失败时检查本机 `.50.2` 地址、DLL 是否齐全以及旧 ADS/ScreenCut 是否占用端口；视频黑屏还要检查相机地址、网口和主端相机凭据。
- 截图先确认本地预览和持续发送提示，再检查主端 UDP 端口、防火墙，以及是否运行了旧影像主端占用端口。快发目标 `.50.2` 配错只会影响调速；收不到任何首帧还需排查截图和入站 UDP 链路。
