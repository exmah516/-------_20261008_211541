# 数据端使用

1. 将整个 `ScreenCut` 文件夹复制到数据端，不要只复制 EXE。
2. EXE.config 设置主端 `192.168.50.1`、本机 `192.168.60.1` 和两路相机 IP/网口；`config/hik_cameras.ini` 填相机凭据，两节都用 `stream=1` 子码流。
3. 数据端放行 TCP 8889、UDP 8189 和 TCP 8189；UDP 是低延迟首选，TCP 8189 仅作为建连时 UDP ICE 不可用的备用候选。启动 ScreenCut，预览桌面裁剪区域，点“开始传图”。
4. 主端启动 ImagingMaster；三路视频自动连接。没有接入的摄像头会单独显示无画面，不应影响 DSA 或另一路摄像头。主端 3 秒无解码帧时遮住旧画面，8 秒无解码帧才重建会话。停止传图仅停 DSA，关闭 ScreenCut 才关闭媒体服务。

摄像头必须输出普通 H.264，不用海康 SDK。完整配置表、回环测试和故障定位见上级 `README.md`。

2 Mbps 链路：DSA配置 `VideoWidth=960`、`VideoHeight=540`、`VideoFps=25`、`VideoBitrateKbps=512`。在每台相机网页/iVMS的“视频/音频 → 子码流”中设普通H.264、640×360或640×480、15fps、128kbps CBR、I帧间隔15、无音频，关闭H.264+/H.265/B帧。程序直接中继相机码流，不能代替相机设置。三路视频合计约768kbps，给控制和重传留余量；放大画面清晰度会降低。

已有运行包配置不会被编译脚本覆盖。更新时要同步上述值和INI的 `stream=1`，同时保留现场IP、密码、网卡、截图区域。

日志自动保存在 **ScreenCut.exe 同目录**：`streaming.log` 为当前日志，`streaming.1.log`～`streaming.3.log` 为较早记录（1最新）。正常提示和异常都会逐条写盘，带毫秒时间，RTSP凭据脱敏；每份约2 MB，总计约8 MB，不在内存积攒历史。重启继续追加；窗口只刷新最新提示。发生断连后把这四份文件一起保留即可。旧版 `%LOCALAPPDATA%/VI.Imaging/logs/streaming.log` 仍留在原处。

仅本次日志更新：关闭数据端 ScreenCut，替换新版 `ScreenCut.exe` 即可，现有配置和运行库无需改动。
