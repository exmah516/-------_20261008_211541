# 有线网络分机部署与画质设置

三个程序分别更新完整文件夹：截图电脑用“B数据端/截图端”，监控电脑用“B数据端/监控端”，主端用“A主端/运行”。主端现在随包运行本地 MediaMTX，同时提供三路显示和原码流录像。

```text
截图端 192.168.2.27:8889 ──WHEP──┐
监控端 192.168.60.1:8890 ─WHEP──┴→ 主端 MediaMTX → 本机 WebView2
                                         └──→ recordings/会话目录
```

## 1. 三台电脑和两条链路

| 链路 | 发送端 IPv4 | 主端对应网口 IPv4 | 信令 TCP | 媒体 UDP/TCP |
| --- | --- | --- | --- | --- |
| 截图 | 192.168.2.27 | 192.168.2.21 | 8889 | 8189 |
| 监控 | 192.168.60.1 | 192.168.50.1 | 8890 | 8190 |

监控与机器人控制共用网线，保留机器人现有网络配置。监控两端地址不在同一 /24：直连时需要现有掩码覆盖两端（例如 255.255.0.0），或具备正确路由。先核对现场掩码和路由；软件及构建脚本不会修改 Windows 网卡。

截图包需要 runtime/ffmpeg.exe 和 runtime/mediamtx.exe；监控包和主端包各需要自己的 runtime/mediamtx.exe。主端还需 WebView2 Evergreen Runtime。复制整个文件夹，关闭旧版本后替换；保留监控相机配置。构建仍保留已有运行配置，本次交付目录中的网络 INI/XML 已按上表显式更新。

## 2. 完整网络配置与连通性

截图端 streaming.config：

```xml
<?xml version="1.0" encoding="utf-8"?>
<appSettings>
  <add key="MasterIp" value="192.168.2.21" />
  <add key="RelayListenIp" value="192.168.2.27" />
  <add key="WebRtcPort" value="8889" />
  <add key="WebRtcMediaPort" value="8189" />
  <add key="LocalRtspPort" value="8554" />
  <add key="LocalApiPort" value="9997" />
</appSettings>
```

监控端 streaming.config：

```xml
<?xml version="1.0" encoding="utf-8"?>
<appSettings>
  <add key="MasterIp" value="192.168.50.1" />
  <add key="RelayListenIp" value="192.168.60.1" />
  <add key="WebRtcPort" value="8890" />
  <add key="WebRtcMediaPort" value="8190" />
  <add key="LocalRtspPort" value="8555" />
  <add key="LocalApiPort" value="9998" />
</appSettings>
```

主端 config/dsa_screencut.ini：

```ini
screenCutIp=192.168.2.27
webrtcPort=8889
streamPath=stream_dsa

[relay]
webrtcPort=8891
mediaPort=8191
apiPort=9999
recordingRoot=recordings
```

主端 config/hik_cameras.ini：

```ini
[camera1]
name=监控 1
ip=192.168.60.1
webrtcPort=8890
streamPath=stream_cam1

[camera2]
name=监控 2
ip=192.168.60.1
webrtcPort=8890
streamPath=stream_cam2
```

两份主端 INI 只保存上游与录像设置。主端三路实际播放地址为 http://127.0.0.1:8891/stream_dsa/whep、stream_cam1/whep、stream_cam2/whep；端口来自 [relay]。API 9999、信令 8891、媒体 8191 仅监听 127.0.0.1，无需向其它电脑放行。

上述限定针对本地播放服务。MediaMTX 作为 WHEP 客户端取远程流时，ICE 还会在可用网卡上创建临时 UDP 套接字；这些用于上游拉流，不是额外开放的播放服务。

相机实体设置保持原值：相机 1 为 192.168.1.64，经本地 192.168.1.97、RTSP 554；相机 2 为 192.168.1.32，经本地 192.168.1.96、RTSP 554。当前监控端 INI 两路均为 username=admin、channel=1、stream=1（RTSP 102，子码流），现有密码保持不变。完整私有配置见交付报告与监控端原文件。

在主端先运行：

```powershell
Test-NetConnection 192.168.2.27 -Port 8889 -InformationLevel Detailed
Test-NetConnection 192.168.60.1 -Port 8890 -InformationLevel Detailed
Test-NetConnection 192.168.2.27 -Port 8189 -InformationLevel Detailed
Test-NetConnection 192.168.60.1 -Port 8190 -InformationLevel Detailed
Find-NetRoute -RemoteIPAddress 192.168.2.27
Find-NetRoute -RemoteIPAddress 192.168.60.1
```

截图链路 SourceAddress 必须为 192.168.2.21，监控链路必须为 192.168.50.1。WHEP 客户端使用系统选路，没有额外的源地址绑定项。发送端继续只授权各自的 MasterIp；源地址不符时修正现场选路，不能放宽授权。开发机此次检查两条路由均选到了 WLAN 192.168.43.10，且缺少 .2.21，因此实际双机授权尚待现场验收。

发送端防火墙仅对对应的主端地址允许入站：

| 电脑 | 来源 | TCP | UDP |
| --- | --- | --- | --- |
| 截图 | 192.168.2.21 | 8889、8189 | 8189 |
| 监控 | 192.168.50.1 | 8890、8190 | 8190 |

8554/8555（RTSP）和 9997/9998（API）维持仅本机访问，不增加跨机开放。主端需要允许 MediaMTX 到两台发送端的 WHEP/ICE 出站及对应返回流量；本地服务无需外部入站规则。以上 TCP 检查不能证明 UDP 媒体可用，最终以画面解码和录像文件为准。

## 3. 快速调整截图分辨率、帧率、码率

在 ScreenCut 窗口下排选“画质档位”，或者直接填写输出宽、高、帧率和码率，再点 **“开始传图 / 应用画质”**。设置会保存到 ScreenCut.exe.config；正在传图时仅重新启动截图编码，主端自动恢复，无需重启监控或主端。

| 档位 | 输出分辨率 | 帧率 | 码率 kbps | 用途 |
| --- | --- | --- | --- | --- |
| 低带宽 | 960×540 | 25 | 512 | 原 2 Mbps 链路配置 |
| 清晰 | 1280×720 | 25 | 2500 | 降低截图电脑编码负载或网络占用 |
| 高清（推荐起点） | 1920×1080 | 25 | 6000 | 有线网络先试此档 |
| 精细 | 1920×1080 | 30 | 10000 | 动态细节较多且编码性能足够时试用 |

这些是本项目提供的试用参数，不是所有画面的最低码率保证。1 Mbps = 1000 kbps。可手动输入宽 320–1920、高 180–1080（均须为偶数）、帧率 10–30、码率 128–20000 kbps。上排“左、上、宽、高”决定**截哪块桌面**；下排“输出宽、高”决定传输图像大小。只截了 640×480 再放大到 1080p，不会增加原始细节；尽量截取需要的原始区域。

也可退出截图软件后编辑配置，再启动：

```xml
<add key="VideoWidth" value="1920" />
<add key="VideoHeight" value="1080" />
<add key="VideoFps" value="25" />
<add key="VideoBitrateKbps" value="6000" />
```

画面细节不够时先确认截图原始区域，再提高码率；有卡顿时检查 CPU 和网卡负载，可退到 720p 或降低帧率。修改码率不改变主端既有的约 1 秒接收缓冲目标，本次不调整延迟策略。

## 4. 快速提高两路海康监控画质

监控软件直接转发相机原码流，修改截图参数不会改变相机画质。需要先在**每台相机网页或 iVMS 的视频/音频设置**里设置码流，再在监控端 INI 里选对应码流。

建议把主码流设置为普通 H.264、1920×1080、25 fps、4096 kbps CBR、I 帧间隔 25，关闭 H.264+、H.265、B 帧和音频；设备不支持某项时使用其实际支持的分辨率/帧率。画面细节不足且链路稳定时，可试每路 6144 或 8192 kbps，具体数值以设备支持为准。

然后编辑**监控端** config/hik_cameras.ini，在两节中都设置：

```ini
[camera1]
; 保留该节原有 username 和 password
channel=1
stream=0

[camera2]
; 保留该节原有 username 和 password
channel=1
stream=0
```

只修改原文件的 channel/stream 行，保留用户名密码。stream=0 选择主码流（通道 1 对应 RTSP 101），stream=1 选择子码流（102）。不要把这段带占位注释的片段当成完整凭据文件替换。设置后重启监控软件，主端无需改动。首次打包会保留原来的 stream 值，不会擅自把正在使用的子码流改成主码流。

便于以后快速切换，可把相机主码流设为高清，子码流设为低带宽；切换 INI 的 stream 值并重启监控即可。相机 IP、网卡和端口错误时，可双击监控端“检查相机连接.cmd”，该工具只检查 TCP 连通性。

## 5. 主端录像与带宽

主端本地中继以 WHEP 为 source，每路持续拉取一次（sourceOnDemand: false）；本机显示和录像共用该输入。不转码，录像保持输入 H.264 编码，CPU 主要用于转发和写盘。窗口最小化、隐藏或暂时停止呈现，不会暂停录像。

采用此方案是为了避免监控与机器人共用网线增加一份视频流量。WebView MediaRecorder 方案需要重新编码，显示暂停或窗口隐藏可能丢帧；发送端另开远程 RTSP 录制会再拉一次流、使视频网络流量翻倍，并需开放当前仅供本机使用的 RTSP。因此不采用这两种方案。

默认保存到主端 EXE 同目录的 recordings；[relay] recordingRoot 可填相对 EXE 的目录或绝对路径。每次启动创建 yyyy-MM-dd_HH-mm-ss-fff 会话目录，结构例如：

```text
recordings/2026-11-10_09-30-00-123/
  mediamtx.yml
  mediamtx.log
  stream_dsa/2026-11-10_09-30-01-123456.mp4
  stream_cam1/2026-11-10_09-30-01-234567.mp4
  stream_cam2/2026-11-10_09-30-01-345678.mp4
```

文件为 fMP4，一秒一个写入分片，不会每秒新建文件。分段设为该版本允许的最大值 24h：连续运行不足 24 小时时每路一个文件；超过 24 小时会分段。断流重连、发送端重新编码、主端中继重启也会产生新文件，仍属于同一主端会话目录。不自动删除录像（recordDeleteAfter: 0s）。

正常关闭主端时等待 MediaMTX 响应 Ctrl+C 并写完最后一段。强制结束时，已落盘的 fMP4 分片仍可播放，最后约一秒未完成的分片可能损失。状态区“录像中：<会话目录>”依据文件实际增长刷新；某路等待视频或发生错误时，同一行说明原因。完整原因见该会话 mediamtx.log。

以截图 6000 kbps、两相机各 4096 kbps 计算，视频合计 14.192 Mbps；每小时约 6.39 GB（约 6.3 GB，5.95 GiB），另有少量封装。截图链路约 6 Mbps，监控链路约 8.192 Mbps，加协议与机器人业务流量。当前两路相机仍选用原子码流，这个容量是上述设定码率的估算，不代表现场当前实测码率。

现场统计监控网卡：在主端找到 192.168.50.1 所在适配器，以 30 秒接收字节差估算 Mbps，同时在监控电脑本机 API 确认每路 readers 只有 1 个：

```powershell
$nic = (Get-NetIPAddress -IPAddress 192.168.50.1).InterfaceAlias
$before = Get-NetAdapterStatistics -Name $nic
$clock = [Diagnostics.Stopwatch]::StartNew()
Start-Sleep -Seconds 30
$after = Get-NetAdapterStatistics -Name $nic
($after.ReceivedBytes - $before.ReceivedBytes) * 8 / $clock.Elapsed.TotalSeconds / 1e6
# 在监控电脑执行：
Invoke-RestMethod http://127.0.0.1:9998/v3/paths/get/stream_cam1
Invoke-RestMethod http://127.0.0.1:9998/v3/paths/get/stream_cam2
```

网卡统计包含机器人控制与其它流量，需记录测量期间的业务状态。主端本机录像不会增加监控电脑的 readers 数量。

## 6. 更新和验收顺序

1. 三台电脑关闭旧程序，各自复制完整新运行包；监控相机配置和密码保持原值。
2. 核对两条链路的实际 IP、掩码、路由和上述防火墙规则。
3. 启动两个发送软件；截图端预览区域后点击“开始传图 / 应用画质”，监控端自动接入。主端运行 Test-NetConnection 并核对 SourceAddress。
4. 启动主端，确认三路画面与主画面切换正常，状态显示录像目录，三个子目录中的 MP4 持续增长。
5. 分别停开截图端和监控端，确认另一端显示与文件继续增长；恢复后对应路新建 MP4。也可交换主端与发送端启动顺序检查。
6. 最小化主端后检查文件仍增长；正常关闭主端，用播放器抽查三路最后文件。
7. 测量监控主端网卡流量并保存结果，与监控端单读者 API 记录一并验收。

截图日志为 streaming.log，监控日志为 monitoring.log；主端日志跟随每次录像会话保存。离线检查运行“单机回环测试.ps1 -RecordingOnly”，原显示、认证、弱网检查仍可运行不带参数的脚本。离线证据及未验证事项见“验证结果.md”和私有交付报告。
