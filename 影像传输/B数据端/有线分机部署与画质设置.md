# 有线网络分机部署与画质设置

截图端和监控端可以部署在两台不同的电脑上，各自启动自己的媒体服务。两端互不连接，主端分别向它们取图。也可以部署在同一台电脑，保留默认不同端口即可。

## 1. 分别复制两个完整运行包

- 截图电脑：复制整个“截图端”文件夹，启动 ScreenCut.exe。
- 监控电脑：复制整个“监控端”文件夹，启动 CameraMonitor.exe。
- 主端电脑：沿用原 ImagingMaster.exe，只修改原运行目录 config 下的两份 INI。

不要只复制 EXE。截图端需要 runtime/ffmpeg.exe 和 runtime/mediamtx.exe；监控端只需要 runtime/mediamtx.exe。首次构建会沿用旧包的相机凭据、绑定网口和截图区域；新截图包初始化为 1080p25、6000 kbps。后续构建保留这两份独立运行包中已有的现场配置。旧“运行”和“ScreenCut”目录保留用于兼容与迁移。

## 2. 配置三个电脑地址

以下是**示例地址**，新运行包按这组地址预填，不会修改 Windows 网卡；请让配置与各电脑实际有线 IPv4 一致。三台接同一交换机时，可使用同一网段和相同子网掩码，例如下表均为 /24（255.255.255.0）。同时使用其他业务网卡时，避免与现有网段冲突。

| 电脑 | 示例有线 IPv4 | 软件 |
| --- | --- | --- |
| 主端 | 192.168.2.10 | ImagingMaster |
| 截图电脑 | 192.168.2.20 | ScreenCut |
| 监控电脑 | 192.168.2.30 | CameraMonitor |

截图端文件夹的 streaming.config：

```xml
<?xml version="1.0" encoding="utf-8"?>
<appSettings>
  <add key="MasterIp" value="192.168.2.10" />
  <add key="RelayListenIp" value="192.168.2.20" />
  <add key="WebRtcPort" value="8889" />
  <add key="WebRtcMediaPort" value="8189" />
  <add key="LocalRtspPort" value="8554" />
  <add key="LocalApiPort" value="9997" />
</appSettings>
```

监控端文件夹的 streaming.config：

```xml
<?xml version="1.0" encoding="utf-8"?>
<appSettings>
  <add key="MasterIp" value="192.168.2.10" />
  <add key="RelayListenIp" value="192.168.2.30" />
  <add key="WebRtcPort" value="8890" />
  <add key="WebRtcMediaPort" value="8190" />
  <add key="LocalRtspPort" value="8555" />
  <add key="LocalApiPort" value="9998" />
</appSettings>
```

MasterIp 填主端实际 IP（限定谁能读视频）；RelayListenIp 填**运行该软件的电脑**实际 IP，不能填另一台电脑或实体摄像头 IP。每份配置独立修改，保存后重启对应软件即可。跨网段部署需要三台电脑之间实际可路由。

主端**实际运行目录**的 config/dsa_screencut.ini：

```ini
screenCutIp=192.168.2.20
webrtcPort=8889
streamPath=stream_dsa
```

主端实际运行目录的 config/hik_cameras.ini：

```ini
[camera1]
name=监控 1
ip=192.168.2.30
webrtcPort=8890
streamPath=stream_cam1

[camera2]
name=监控 2
ip=192.168.2.30
webrtcPort=8890
streamPath=stream_cam2
```

保存两份 INI 后重启主端。这里的 camera1/2 IP 指向**监控电脑**。实体相机的 IP、绑定网口仍填在监控端 CameraMonitor.exe.config；用户名密码、channel 和 stream 填在监控端 config/hik_cameras.ini。这两个同名 INI 位于不同电脑，作用不同。

在对应发送电脑上放行入站（来源为主端 IP）：

| 电脑 | TCP 信令 | UDP/TCP 媒体 |
| --- | --- | --- |
| 截图电脑 | 8889 | 8189 |
| 监控电脑 | 8890 | 8190 |

8554/8555、9997/9998 仅供各电脑本机使用，不需要跨电脑开放。主端可运行下列命令检查 TCP；UDP 媒体最终以实际解码画面为准：

```powershell
Test-NetConnection 192.168.2.20 -Port 8889
Test-NetConnection 192.168.2.30 -Port 8890
Test-NetConnection 192.168.2.20 -Port 8189
Test-NetConnection 192.168.2.30 -Port 8190
```

## 3. 快速调整截图分辨率、帧率、码率

在 ScreenCut 窗口下排选“画质档位”，或者直接填写输出宽、高、帧率和码率，再点 **“开始传图 / 应用画质”**。设置会保存到 ScreenCut.exe.config；正在传图时仅重新启动截图编码，主端自动恢复，无需重启监控或主端。

| 档位 | 输出分辨率 | 帧率 | 码率 kbps | 用途 |
| --- | --- | --- | --- | --- |
| 低带宽 | 960×540 | 25 | 512 | 原 2 Mbps 链路配置 |
| 清晰 | 1280×720 | 25 | 2500 | 降低截图电脑编码负载或网络占用 |
| 高清（推荐起点） | 1920×1080 | 25 | 6000 | 有线网络先试此档 |
| 精细 | 1920×1080 | 30 | 10000 | 动态细节较多且编码性能足够时试用 |

这些是本项目提供的试用参数，不是所有画面的最低码率保证。1 Mbps = 1000 kbps。可手动输入宽 320–1920、高 180–1080（均须为偶数）、帧率 10–30、码率 128–20000 kbps。上排“左、上、宽、高”决定**截哪块桌面**；下排“输出宽、高”决定传输图像大小。只截了 640×480 再放大到 1080p，不会增加原始细节；尽量截取需要的原始区域。

也可退出截图软件后编辑配置，再启动：

```xml
<add key="VideoWidth" value="1920" />
<add key="VideoHeight" value="1080" />
<add key="VideoFps" value="25" />
<add key="VideoBitrateKbps" value="6000" />
```

画面细节不够时先确认截图原始区域，再提高码率；有卡顿时检查 CPU 和网卡负载，可退到 720p 或降低帧率。修改码率不改变主端既有的约 1 秒接收缓冲目标，本次不调整延迟策略。

## 4. 快速提高两路海康监控画质

监控软件直接转发相机原码流，修改截图参数不会改变相机画质。需要先在**每台相机网页或 iVMS 的视频/音频设置**里设置码流，再在监控端 INI 里选对应码流。

建议把主码流设置为普通 H.264、1920×1080、25 fps、4096 kbps CBR、I 帧间隔 25，关闭 H.264+、H.265、B 帧和音频；设备不支持某项时使用其实际支持的分辨率/帧率。画面细节不足且链路稳定时，可试每路 6144 或 8192 kbps，具体数值以设备支持为准。

然后编辑**监控端** config/hik_cameras.ini，在两节中都设置：

```ini
[camera1]
; 保留该节原有 username 和 password
channel=1
stream=0

[camera2]
; 保留该节原有 username 和 password
channel=1
stream=0
```

只修改原文件的 channel/stream 行，保留用户名密码。stream=0 选择主码流（通道 1 对应 RTSP 101），stream=1 选择子码流（102）。不要把这段带占位注释的片段当成完整凭据文件替换。设置后重启监控软件，主端无需改动。首次打包会保留原来的 stream 值，不会擅自把正在使用的子码流改成主码流。

便于以后快速切换，可把相机主码流设为高清，子码流设为低带宽；切换 INI 的 stream 值并重启监控即可。相机 IP、网卡和端口错误时，可双击监控端“检查相机连接.cmd”，该工具只检查 TCP 连通性。

## 5. 总带宽与排错

以截图 6000 kbps、两台相机各 4096 kbps 为例，视频负载约 14.2 Mbps，另有协议封装和其它业务流量。有线部署可先按此配置试用，实际可用带宽由整条路径中最窄的链路决定；网线接入但中间仍走 4G/限速隧道时，仍须按那段带宽设置。

截图日志为截图端 streaming.log，监控日志为监控端 monitoring.log，各有三份轮转历史。主端会自动等待尚未启动的软件；截图或监控故障只影响相应画面。真实设备画质、编码 CPU 占用和交换机链路需现场确认。
