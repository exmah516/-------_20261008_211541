# 主端工程与启动

日常双击本目录的 **编译并启动主端.cmd**。它先编译 Release，再检查依赖，成功后从工程输出启动；构建失败不会打开旧程序。已有主端窗口时先关闭，再重新编译启动。

- 源码：`工程/master/MasterConsole.sln`。请关闭 Visual Studio 中旧路径的解决方案，再打开此文件。
- 默认程序：`工程/master/MasterConsole/bin/Release/net472/MasterConsole.exe`。
- VS 调试：将 MasterConsole 设为启动项目，使用 Debug；程序输出在 `bin/Debug/net472`，仍为 x64。
- 密钥：`工程/config/remote.token`。与从端一致，编译和清理不覆盖它。
- 摄像头配置：`工程/config/hik_cameras.ini`；按现场实际设备修改。不要在 bin 里另放同名配置，以免遮住工程配置。
- 依赖：VC++ 文件保存在 `工程/Runtime/VC142`，其余 SDK、VTK 和 URDF 由原工程配置复制。Debug 与 Release 都会自动补齐。

命令行只编译、不启动：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\工程\build-and-run.ps1 -BuildOnly
powershell -NoProfile -ExecutionPolicy Bypass -File .\工程\build-and-run.ps1 -Configuration Debug -BuildOnly
```

“模拟运行主端.cmd”使用模拟机器人链路。摄像头模块仍按现有配置工作；它不是摄像头离线开关。独立离线模型检查用“验证旧VTK模型运动.cmd”，不创建机器人控制服务。

VTK 测试源码和脚本在 `工程/tools`。网络模型验证仍使用根目录的“接收从端VTK模型.cmd”，由 B 端运行“发送VTK模型测试.cmd”。说明见 `工程/docs/VTK分机测试与摄像头连接说明.md`。测试结果在对应构建输出的 `VTK测试结果` 中。

编译需 .NET SDK、.NET Framework 4.7.2 开发包；首次还原 NuGet 包需联网或已有包缓存。主端连接地址仍为从端 `192.168.50.2`。

旧“运行”内容及历史测试结果保存于 `归档_旧运行_20261010.zip`，不用于日常启动。原文件清单是迁移前的历史记录。

迁移时 Visual Studio 正占用旧路径的两份 `.vsidx` 索引，因此“源码备份”目前只残留这两份 IDE 缓存，没有源码或程序。关闭旧解决方案后可删除此残留目录；实际工程全部位于“工程”。
