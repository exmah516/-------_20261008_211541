# 数据端工程与启动

日常双击本目录的 **编译并启动数据端.cmd**。它先编译 Release x64，再检查依赖，成功后启动工程输出的 ADS.exe；构建失败不会打开旧程序。重新构建完整数据端前先关闭 ADS 和本地调试台。

- 源码：`工程/ADS项目/ADS.sln`。请从此新位置打开解决方案。
- 默认程序：`工程/ADS项目/x64/Release/ADS.exe`。
- VS 调试：选择 Debug / x64，将 ADS 设为启动项目，输出在 `工程/ADS项目/x64/Debug`。
- 密钥：`工程/config/remote.token`。与主端保持一致，编译和清理不覆盖它。
- 依赖：ADS 和手柄 DLL 由工程复制；VC++ 文件在 `工程/Runtime/VC142`，随 Debug、Release 自动复制。
- 本地调试台：双击“编译并启动本地调试台.cmd”。该入口只构建界面项目，可在 ADS 已运行时使用；输出在 `工程/ADS项目/AdsControlUI/bin/Release/net472`。

命令行只编译、不启动（不会连接 PLC）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\工程\build-and-run.ps1 -BuildOnly
powershell -NoProfile -ExecutionPolicy Bypass -File .\工程\build-and-run.ps1 -Configuration Debug -BuildOnly
```

电缸自动夹紧预设在 `工程/ADS项目/control_types.h` 的 `CylinderPreset`：`cyl2_clamp = 1000`、`cyl4_clamp = 1000`。递送、快退后重新夹紧、恢复及锁止等共用此预设；两缸松开值仍为 5，特殊释放、预夹紧、启动专用值和换手时序保持原样。修改后需关闭旧 ADS 进程并通过新入口重新编译启动才能生效。

编译需 Visual Studio 2022 或 Build Tools（MSBuild、C++ v142 工具集、Windows SDK）、.NET SDK 和 .NET Framework 4.7.2 开发包。首次 NuGet 还原需联网或已有缓存。保留现有 IP 和 PLC 配置。

网络模型测试使用 `造影机器人/B数据端/发送VTK模型测试.cmd`，连接主端 `192.168.50.1`；不必启动 ADS。说明见 `工程/docs/VTK分机测试与摄像头连接说明.md`。

旧“运行”内容保存于 `归档_旧运行_20261010.zip`，不用于日常启动。原文件清单是迁移前的历史记录。

## 2026-10-10 ADS 中断恢复

可以直接在 VS 中编译并按 F5 调试，使用 Debug/x64 的 ADS 启动项目。通信中断后停止控制；显示“连接就绪”后点击主端“开始控制”，成功重建当前位置基准后继续，无需仅因通信中断再次进入准备位置。PLC 确认未自检时仍需准备；回退故障锁止不能用“开始控制”绕过。

已修复 PLC `G.gen_state` 的 2 字节 INT 与 C++ 原 4 字节读取/订阅不匹配。首次超时的现场根因仍待复测；新日志记录目标地址和本地/备用连接各自错误。保留 EXE 旁 `ads_fault_diagnostics.log`。完整排查、备份和离线测试记录在软件包 `验证记录/20261010_ADS恢复排查`。

海康监控1转发已集成到 ADS.sln，随 ADS.exe 自动启动和退出。摄像头地址 192.168.1.64:8000，USB 网口地址 192.168.1.96，主端访问 192.168.50.2:18000；详细接线与防火墙设置见 [摄像头接从端说明](摄像头接从端说明.md)。
