# 界面架构说明

## 主端职责

`介入机器人/A主端/工程/master/MasterConsole` 是介入机器人的 WPF 远程操作界面。操作方向为递送/撤出；状态区显示导丝和导管各自的轴向力、扭矩。

界面保留连接终端、准备、开始控制、力反馈及既有器械和定位臂操作。`HandleService` 读取本机双手柄并输出触觉，主端不直接访问 ADS/PLC。

## 通信调用链

界面和视图模型通过 `IRobotLink` 调用 `RemoteRobotLink`；后者使用独立的 `VI.Service.Net`，经 Zenoh-C 1.10.1 连接数据端路由器。主端保持 .NET Framework 4.7.2/x64，仅创建 Client Session。

`VI.Service.Net` 提供 `Advertise<T>()`、`Subscribe<T>()`、`Serialize<T>()`、`Deserialize<T>()`。主端发送 handle/command，接收 state/force；MessagePack 位置数组由两端协议类型严格镜像。状态接收驱动界面刷新，力目标送给本机手柄。

连接成立需要 Zenoh Session 可用且最近有效 state 帧不超过 500 ms。UI 命令仅在 Publisher 可用时发送，不缓存或补发；结果以及准备位置、开始控制的专用任务状态通过 state 返回。高频点动与保活不进入普通命令结果队列。

## 数据端边界

`ADS.exe` 不包含本地调试 UI、键盘控制或命名管道后端。`ZenohService` 把网络命令转换成 `control_messages.h` 的 `VisCommand`，由原控制循环继续处理，保留原有安全门控和 PLC 急停路径。

`control_messages.h` 中的状态和命令是内部控制域类型；线格式由 `ZenohFrames.cs` 与 `protocol/cpp/zenoh_protocol.h` 定义。字段、认证和 Topic 约定见本端 `工程/protocol/PROTOCOL.md`。

运行入口见各端 `使用说明.md`。实验数据格式见 [实验记录说明](../guides/实验记录说明.md)。造影模型、截图与监控界面由另外两个业务工程负责。
