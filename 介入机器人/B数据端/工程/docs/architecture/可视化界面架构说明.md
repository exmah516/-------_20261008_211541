# 界面架构说明

## 主端职责

`介入机器人/A主端/工程/master/VI.Control` 是 .NET 8 WPF、x64 远程操作界面。解决方案入口为 `master/VI.Control.slnx`，SDK 固定为 9.0.315。操作方向为递送/撤出；顶部显示导丝和导管各自的轴向力、扭矩。

界面保留连接终端、准备、开始控制、力反馈及既有器械和定位臂操作。`HandleService` 读取本机双手柄并输出触觉，主端不直接访问 ADS/PLC。

浅色控制台同屏排列 `intervention`（介入控制）和 `positioning-arm`（定位臂）两个可折叠面板，小窗口通过滚动访问。连接/断开和操作结果放在操作区，不设置连接状态栏或日志面板；模拟模式明确标注。原主题、视图模型门控、参数范围、单位换算和数据端确认继续复用。

## 框架和动态模块

`Robotics.HostFramework` 与 `Robotics.HostFramework.Contracts` 为本地 Release 二进制 NuGet 包，目标 `net8.0-windows`，精确版本 `[0.1.0-dev]`。Hosting、DI 依赖为 8.0.1。两个包由 `NuGet.Config` 的源映射限定到 `Packages`，框架源码位于交付仓库之外的 `重构框架/HostFramework`。

`App` 继承 `HostApplicationBase`，通过宿主配置、日志、服务注册和窗口创建扩展点组装应用。启动依次扫描根目录、`Modules/Platform`、`Modules/Features`；查找实现 `IModule` 的 `[FeatureModule]` 类型，执行 `[ConfigureServices]` 静态依赖注册，再构建 DI、校验元数据，在 WPF Dispatcher 注册面板工厂并启动受管服务。扫描阶段不会创建完整面板或初始化设备。必需模块缺失、重复 ID、加载或注册失败终止启动并报告具体原因。

`ModuleMetadata` 定义 ID、标题和顺序；`IModule.Register(IShellRegion, IServiceProvider)` 通过 `RegisterPanel(metadata, factory)` 注册。两个业务模块共享 DI 中的 `MainViewModel`、`IRobotLink` 和手柄。模块 DLL 和资源部署在模块目录，Contracts、框架与共享业务依赖只在应用根目录提供一份；首版统一使用 `AssemblyLoadContext.Default`，随进程启动加载。新增共享依赖须由主程序引用并进入应用 `.deps.json`，复制未声明的依赖 DLL 不保证能够解析。

受管服务用 `AddManagedHostedService<T>()` 注册，通过 `[StartupDependsOn]` 排序启动、逆序停止，缺失依赖和循环依赖在启动前拒绝；部分启动失败回滚已启动服务。手柄不在构造函数启动线程，宿主负责显式 Start/Stop 和唯一释放。模拟模式仅注册模拟链路，不解析或启动真实手柄 SDK。

## 通信调用链

界面和视图模型通过 `VI.Service.Robot` 的 `IRobotLink` 调用 `RemoteRobotLink`；后者使用独立的 `VI.Service.Net`，经 Zenoh-C 1.10.1 连接数据端路由器。通信与纯协议程序集为 `net8.0`，主端仅创建 Client Session。机器人 SDK、序列号、标定及协议保留为业务源码。

`VI.Service.Net` 提供 `Advertise<T>()`、`Subscribe<T>()`、`Serialize<T>()`、`Deserialize<T>()`。主端发送 handle/command，接收 state/force；MessagePack 位置数组由两端协议类型严格镜像。状态接收驱动界面刷新，力目标送给本机手柄。

连接、操作新鲜度与失联清力统一使用最近一帧通过认证、会话及严格递增序号校验的 state 本机接收时间；间隔达到 2000 ms 即失效。无效帧不刷新时间。超时锁定操作、清除持续输入并撤销本地手柄力，后续 force 不能重新写入；状态恢复后仅消费新收到且序号有效的力帧，不回放旧目标。独立 force 过期保护保留 3000 ms。主动断开与退出立即清力；松手、丢失鼠标捕获和关闭停止点动，窗口失焦不新增停止行为。

UI 命令仅在 Publisher 可用时发送，不缓存或补发；结果以及准备位置、开始控制的专用任务状态通过 state 返回。高频点动与保活不进入普通命令结果队列。

## 离线验证

`tools/verify-migration.ps1` 使用全新 NuGet 缓存还原并构建 Debug/Release x64，检查本地包来源、包内容、运行文件和原生 DLL；协议及 2 秒保护测试在 `MasterConsole.Protocol.Tests`，界面与交互检查在 `VI.Control.Tests`。`tools/check_master_ui.ps1` 生成各窗口尺寸/DPI 的检查图。框架维护目录内另有独立假模块与生命周期验证；C++ 内存模拟数据端回环由 B 端 `ADS项目/tests/run-zenoh-tests.ps1` 执行。这些检查不连接真实设备。

## 数据端边界

`ADS.exe` 不包含本地调试 UI、键盘控制或命名管道后端。`ZenohService` 把网络命令转换成 `control_messages.h` 的 `VisCommand`，由原控制循环继续处理，保留原有安全门控和 PLC 急停路径。

`control_messages.h` 中的状态和命令是内部控制域类型；线格式由 `ZenohFrames.cs` 与 `protocol/cpp/zenoh_protocol.h` 定义。字段、认证和 Topic 约定见本端 `工程/protocol/PROTOCOL.md`。

运行入口见各端 `使用说明.md`。实验数据格式见 [实验记录说明](../guides/实验记录说明.md)。造影模型、截图与监控界面由另外两个业务工程负责。
