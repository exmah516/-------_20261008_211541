# 项目架构总览

## 工程位置

介入机器人分为 A主端、B数据端、C从端：A 运行 WPF `VI.Control`（.NET 8、x64）；B 运行 C++ `ADS.exe`；C 保留现场 PLC 工程。

- A：`介入机器人/A主端/工程/master/VI.Control.slnx`。
- B：`介入机器人/B数据端/工程/ADS项目/ADS.sln`。
- 启动和网络配置见软件包根目录的 `主从分机部署教程.md`，各端入口见对应 `使用说明.md`。

## 模块边界

主端负责介入界面、本机手柄采样和触觉输出。界面仍通过 `IRobotLink` 调用；`RemoteRobotLink` 使用独立的 `VI.Service.Net`，以 Zenoh Client Session 连接数据端路由器，默认地址为 `tcp/192.168.60.1:7447`。主端不启动路由器，也不直接访问 ADS/PLC。

数据端负责 ADS 通信、原有运动流程、力采集与反馈、定位臂和实验记录。`ZenohService` 独立处理认证、会话、Topic 与消息收发，并负责启动或复用 `zenohd.exe`；只关闭本进程启动的路由器。收到的业务指令转换为 `control_messages.h` 中的 `VisCommand`，交给原控制循环和安全门控处理。

两端只使用四个 MessagePack 位置数组 Topic：

| Topic | 方向 | 频率/用途 |
|---|---|---|
| `vi/ads/handle/v1` | 主端 → 数据端 | 100 Hz，双手柄采样、按键和控制增量 |
| `vi/ads/command/v1` | 主端 → 数据端 | 按需，UI 指令与认证 |
| `vi/ads/state/v1` | 数据端 → 主端 | 约 30 Hz，运行状态、命令结果与长任务状态 |
| `vi/ads/force/v1` | 数据端 → 主端 | 100 Hz，手柄力反馈目标 |

网络字段由 `ZenohFrames.cs` 与 `protocol/cpp/zenoh_protocol.h` 镜像定义。`control_messages.h` 仅定义数据端控制域类型，不作为网络字节布局。协议以本端 `工程/protocol/PROTOCOL.md` 为准。

## 控制循环与 PLC 边界

ADS 通信线程按 100 Hz 读取快照并应用输出。主循环消费快照与远程指令，推进准备、递送/撤出及换手流程，发布运动与力反馈输出，并将实验样本送入异步记录线程。定位臂由独立 ADS 服务管理。

Zenoh 命令 FIFO 容量为 256；队满丢弃最旧项并记日志，入队超过 2 秒的命令拒绝执行。手柄高频通道独立处理。时间采用本机单调时钟；主端依据 Echo 计算 RTT，不比较两台电脑的绝对时间。连接判定为 Session 可用且最近有效 state 接收间隔小于 2000 ms。

本次替换通信传输，保留控制流程和 PLC ADS 契约。PLC 急停沿用独立路径；网络不增加软件急停。`arm_stop` 只停止定位臂。
