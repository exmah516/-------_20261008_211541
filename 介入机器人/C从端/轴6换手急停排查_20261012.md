# 轴6换手后短暂急停：2026-10-12 修复与复测

正式 PLC 工程：`下位机工程程序/250902/Untitled2`。上位机：`64位ADS - 相对路径 - 传数组 - 加上手柄`。

## 现象与已确认结论

现场发生在导丝手柄触发换手、轴6回退到位、电缸4尚未动作时。用户观察 `host_comm_timeout=FALSE`，回退 `Req/Busy` 曾为 TRUE、`Error=FALSE`，轴 `Status.Error` 似乎为 FALSE，`Status.Disabled` 短暂为 TRUE。手动监视不保证这些值属于同一个 PLC 扫描周期。

正式代码在任一轴 `G.power_output[i].Done=FALSE`，或任一轴 Axis/Power/Reset 报错时，进入 `_err` 并置 `estop_hold_req=TRUE`。MAIN 的 POWERED 动作把 `MC_Power.Status` 映射到这里的 Done；它不是回退运动完成位。因此轴 Error 为 FALSE 也能进入急停。错误恢复代码随后可能切换 Power，再经 `_clear_err` 的 200 ms 稳定等待和手柄重初始化解除急停。这也意味着观察到的 Disabled 可能是初始事件，也可能是恢复动作的结果。

倍福官方定义 `16#04466` 为编码器 I/O 数据连续多个 NC SAF 周期无效，典型来源包括 EtherCAT WcState 异常或实时负载/抖动；`16#04650` 表示驱动未就绪，可能源于驱动错误、启动阶段或缺少控制器使能。因此后者可以是前者后的状态，不能据此认定 `MC_Power` 误触发。现场 Watch 读到的 `IoDataInvalid=FALSE` 与 `WcState=0` 只代表读取时点，不能排除更早的短暂异常。

回退状态机没有直接将 `G.power_[6].Enable` 置 FALSE。`Disabled` 一次瞬态不能证明是谁撤销使能，也不能排除其他轴先触发全局恢复。现场新增证据为：`estop_diag_axis[6].IoDataInvalid=FALSE`、Drive 14 `WcState=0`，且从站没有离开 OP；因此不能把当前事件定性为持续 EtherCAT 掉线，`4466` 更可能是已恢复的瞬态错误或错误码在复位前的保留值。

## 本次改动

1. 状态 30 已经锁存停稳位置，但状态 31 和完成后的等待窗口仍接受主机写入的回退目标/较旧位置快照，覆盖保持值。现在在接管结束并收到 Req 清零前持续保持锁存位置和零速度/加速度，保留重新使能前的 Feed 预送。
2. 去除“接近目标且不 Busy 即成功”的判定。先处理 Error/CommandAborted，再处理真实 Done，避免误报完成。
3. 在手柄模式进入原急停分支时保存全部 7 轴故障快照，恢复后可读取。
4. 上位机原“ADS 快照中断”提示改为“ADS/PLC 运动条件未就绪”，附带新快照、位置有效性、连接状态、手柄重初始化、超时、PLC 状态及连续失败数。运动门控不变；原提示也可能由 PLC 尚未就绪引起，不能单凭文字判定 ADS 链路断开。
5. `MC_ExtSetPointGenEnable/Disable` 改为单点调用：`handle` 只更新 `Execute` 输入，MAIN 的 `SETPOSITIONGEN` 每个 PLC 扫描只调用一次功能块，消除同一扫描重复更新 FB 状态机的情况。

没有改变回退速度/加速度/加加速度参数、限位保护、2 秒看门狗或自动恢复流程。已调整外部给定功能块的调用职责，避免 MAIN 与 handle 重复调用；其余急停条件保持不变。

## 现场观察

在正式工程重新编译下载后，重新连接上位机。在无患者、允许进行运动测试的台架状态下复测换手。新变量是 PLC 内部锁存，不需要抢看瞬态，也不要手动改写它们。

优先加入 TwinCAT Watch：

```text
G.estop_diag_count
G.estop_diag_host_timeout
G.estop_diag_power[6].Done
G.estop_diag_power[6].Error
G.estop_diag_power[6].ErrorID
G.estop_diag_power_enable[6]
G.estop_diag_power_positive[6]
G.estop_diag_power_negative[6]
G.estop_diag_axis[6].Disabled
G.estop_diag_axis[6].Error
G.estop_diag_axis[6].ErrorID
G.estop_diag_axis[6].DriveDeviceError
G.estop_diag_axis[6].DriveLimitActive
G.estop_diag_axis[6].IoDataInvalid
G.estop_diag_return_state[6]
G.estop_diag_return_cmd[6]
G.estop_diag_reset[6]
```

计数增加后，先保存整组 `estop_diag_*` 的值，再继续测试，避免下一次事件覆盖。确认读取前后 count 相同；同时展开 `[1..7]` 的 `estop_diag_power/axis/reset` 查找首个异常轴。计数为零时默认值无诊断意义。

- `power[6].Done=FALSE`、`power_enable[6]=TRUE`：急停入口时程序仍请求轴6使能，但 Power 状态未就绪。再看同拍轴状态、Power 错误码、驱动状态及 I/O 状态；不能据此直接认定驱动硬件损坏。
- `power_enable[6]=FALSE`：急停入口前使能命令已经撤销，沿 Power 命令写入来源继续查。
- `return_state[6]=31`：发生在外部给定重新接管窗口。对照 enable_error/error_id 与 feed_pos/feed_vel、act_pos/act_vel、refer_abs，判断是否与交接有关。state=0 时结合 return_cmd.Done 判断是否尚在等待主机清 Req。
- 轴6锁存健康、其他轴异常：本次全局急停应从该轴查起，不能只盯轴6。
- `return_cmd.Error=FALSE` 不排除 Power 异常：全局急停检查先于回退状态机执行，可能直接返回而来不及发布回退 Error。

若只有“运动条件未就绪”而 count 不增加，保存完整的新提示行。`ads_state=2` 表示 Running；`handle_reinit_done=0` 表示手柄模式未完成初始化，`new_snapshot=0` 表示该控制轮没有新快照。各字段来自原有快照/通知缓存，并非一份同步 PLC 故障快照。

## 已执行的验证与边界

既有的回退状态机检查曾通过 7 项软件测试，但它不模拟真实 NC 功能块调用、TwinCAT MAIN 的 FBD 调度或 EtherCAT。本次遵照用户要求未编写或运行 Python 测试。此次新增验证仅检查 PLC XML、功能块调用唯一性和文件差异。

上位机 Release/x64 已在独立输出目录编译通过；存在原有手柄.cpp 的 C4819 编码警告，未修改该文件。PLC XML、引用字段与现有 TMC 已检查，源文件保留 UTF-8 和 CRLF。当前环境未进行 TwinCAT 编译、PLC 下载或实机运动验证。

软件层面可确认的交接参考覆盖与功能块重复调用风险已处理；现场 `4466` 的首发来源仍未能仅凭当前快照定位到硬件链路。`IoDataInvalid=FALSE` 和 `WcState=0` 是故障入口快照时的值，不能排除更早几毫秒的短时无效数据。新增快照捕获的是手柄模式急停入口，不覆盖所有启动/自检错误入口，也不是连续的驱动事件记录。
