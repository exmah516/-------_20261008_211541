# 力反馈说明（当前实现）

## 1. 采集数据

数据端从倍福 ADS 读取四路有符号 INT16，通信周期约 100 Hz：

- `G.fn_1_value`
- `G.ft_1_value`
- `G.fn_2_value`
- `G.ft_2_value`

原始值按 `raw / 1000.0` 换算为 V。轴 2 相对位置同时读取，但当前只保留给导管侧历史重力补偿接口，在线重力补偿仍关闭。

## 2. 零点

开启力反馈前，连续等待并采集 3 帧有效 ADS 数据，四路电压和轴 2 位置分别取平均值：

- `f_zero`
- `ft_zero`
- `fn_2_zero`
- `ft_2_zero`
- `theta0_deg`

后续只使用“当前值 - 零点”的差值，因此标定截距自然抵消。

## 3. 标定和输出

当前斜率：

| 通道 | 斜率 |
|---|---:|
| fn_1 | 0.319519429 N/V |
| ft_1 | 0.620117055 N/V |
| fn_2 | 1.139996290 N/V |
| ft_2 | 0.130548347 N/V |

力矩计算为：

`T = Ft × 3 mm × 0.001`，单位 N·m。

当前死区和限幅：

- 轴向力死区：0.02 N
- 力矩死区：0.01 N·mm（0.00001 N·m）
- 轴向力限幅：±5 N
- 力矩限幅：±20 N·mm

现有标定结果先经过原有 `k_feedback = 1.8`，再统一乘以 `ControlConfig.force_feedback_scale = 0.3`。轴向力和力矩共用这一个全局系数。

## 4. 固定手柄映射

力反馈不再根据 `GuidewireMode`、单手柄或双手柄切换：

- `fn_1 + ft_1` 的结果固定发送到物理 SN582
- `fn_2 + ft_2` 的结果固定发送到物理 SN587

主端状态区对应显示两组四个值：

- 导丝：轴向力、力矩（SN582）
- 导管：轴向力、力矩（SN587）

## 5. 输出门控

只有以下条件同时满足时才输出非零力：

```
力反馈已开启
控制已激活
不在急停保持
零点已完成
当前 ADS 力采样有效
```

否则两只手柄的轴向力和力矩都清零。

结构补偿恒力已删除。重力补偿和旧解耦矩阵仍不参与在线输出。

## 6. 保留的动作策略

- 轴 1 或轴 6 快速回退期间，力反馈锁存进入回退前的最后一拍；回退结束后恢复实时值。
- 自动换手恢复夹爪时，若“力反馈-保持”开启，当前输出仍保持 200 ms 后恢复实时值。这是换手动作策略，不是通信超时兜底。

## 7. 远程兜底时间

- 主端 3 s 未收到有效 HapticFrame：两只手柄力输出清零。
- 从端 3 s 未收到 ControlFrame：按超时处理点动并释放控制租约。
- 主端 3 s 未收到 StatusFrame：状态视为过期。

数据端运动状态机中仍保留 `GuidewireMode`，因为它还参与轴 1/轴 6 的运动路由和自动换手；它已经不再参与力反馈计算。
