# 介入机器人 A主端

工程：`工程/master/VI.Control.slnx`，入口 `VI.Control`，.NET 8 WPF、x64。

Visual Studio 调试时请打开 `工程/master/VI.Control.slnx`，将 `VI.Control` 设为启动项目，并选择 `x64`。不要直接启动 `VI.Service.Robot`、`VI.Service.Net`、协议或模块项目，它们是类库，没有可执行入口；`MasterConsole.sln` 已同步为当前项目的兼容解决方案，也可打开，并将 `VI.Control` 设为启动项目。`VI.Control` 项目已提供“VI.Control (模拟)”和“VI.Control (远程)”两个调试配置。

日常解决方案仅保留六个运行项目。协议与界面测试在 `工程/master/VI.Control.Tests.slnx` 中单独维护，日常编译和启动不构建测试项目。

当前职责：

- 血管介入机器人连接、控制和手柄；
- 递送/撤出方向；
- 器械准备位置、开始控制、力反馈、电缸、Y 阀、轴4、注射器和定位臂。

运行本目录的 `编译并启动主端.cmd`。首次使用先运行 `工程/tools/Prepare-Sdk.ps1` 准备官方 SDK 9.0.315；脚本也接受已安装的 9.0.3xx SDK。构建输出在 `工程/build/Release/bin/VI.Control`。部署时复制整个输出目录，并安装 .NET 8 x64 Windows Desktop Runtime，保留两个 `Modules/Features` DLL 和全部原生运行库。

浅色界面同屏显示导丝/导管四个力与力矩读数，以及“介入控制”“定位臂”两个可折叠面板。小窗口中可折叠、滚动操作区。连接/断开位于介入控制内；错误显示在操作区。隐藏的末端点动与程序归零保持默认隐藏。

无硬件查看界面运行 `模拟运行主端.cmd`，窗口明确显示模拟模式。模拟模式不初始化真实 SDK，连接、申请控制权和开始控制仍需按界面流程触发。

DSA 影像、海康监控和造影机器人模型已拆到各自 A主端工程。

本主端不再启动 DSA CAN、VTK、DSA JPEG 或海康显示服务。


通信使用 Zenoh-C 1.10.1 + MessagePack 3.1.12。数据端先运行，主端默认连接 `tcp/192.168.60.1:7447`；可用 `--host` 更改地址，`--token` 指定密钥文件，`--sim` 选择模拟。未指定密钥时沿用可执行文件旁和上级 `config/remote.token` 的查找行为。两端密钥保持一致，原生 `zenohc.dll` 随构建输出。

连接判定、操作门控和失联清力统一为最近一帧通过认证、会话及序号校验的状态帧接收间隔小于 2000 ms，采用本机单调时间。达到超时即清除持续输入及本地手柄力，阻止迟到力帧重新写入；状态恢复后仅接受后续的新力帧。独立力帧超时仍为 3 秒。主动断开和关闭立即清力；松手、丢失鼠标捕获继续停止点动，窗口切换焦点维持既有行为。
