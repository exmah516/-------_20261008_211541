# 主端 + 从端分机部署教程（2026年10月8日）

本目录由当前项目 Release 输出生成，位于：`D:\Work_files\Vessel intervention Robot\主从分机软件包_20261008_211541`。`A_主端电脑` 复制到主端电脑，`B_从端电脑` 复制到从端电脑。两个包都包含运行文件、共享密钥和对应源码备份；源码备份只是留档，不要从里面启动程序。PLC 工程没有复制到运行包，也没有修改。

## 第一步：复制文件

将两个文件夹整体复制到各自电脑的固定位置，例如 `C:\Robot\A_主端电脑` 和 `C:\Robot\B_从端电脑`。不要只拷贝 exe；每个 `运行` 目录中的 DLL、`URDF`、`HCNetSDKCom` 和配置文件必须保持原有相对层级。主端运行目录包含 MasterConsole、协议 DLL、FLCatheter、VTK/URDF、海康 SDK 和 DSA 相关运行库；从端运行目录包含 ADS、TcAdsDll、FLCatheter 以及本地调试台的可选文件。主端需要两只手柄和 SDK 驱动，从端不需要手柄，但 ADS.exe 仍要求 FLCatheter.dll 文件存在。

主端需要 Windows 10/11 x64、.NET Framework 4.7.2 或 4.8、Visual C++ x64 Release 运行库和手柄驱动。从端需要 Windows 10/11 x64、TwinCAT ADS Router 或兼容 ADS 运行环境、Visual C++ x64 Release 运行库；运行 ADS.exe 不需要 Visual Studio。只有重新编译源码时才需要 Visual Studio、MSBuild 和 Eigen/运动学源码。不要把 Debug 运行库复制到现场机。

## 第二步：填写密钥和可选设备配置

两个包根目录的 `运行emote.token` 当前来自项目现有密钥，必须保持内容完全一致，不要打印或提交到网络。主端若使用 DSA 图像，复制 `config\dsa_screencut.ini.example` 为 `config\dsa_screencut.ini` 并填写 ScreenCut 地址；若使用海康相机，复制 `config\hik_cameras.ini.example` 为 `config\hik_cameras.ini` 并填写相机地址、用户名和密码。没有这些设备时不要填写虚假地址，也不会影响主从控制链路。主端连接参数是 `--host <从端IP> --token remote.token`，协议端口由程序固定为 TCP 32000 和 UDP 32001。

## 第三步：设置网络

建议使用隔离网段。主端 A 与从端 B 的直连网卡分别设为 `192.168.50.1/24` 和 `192.168.50.2/24`，这条网卡不设置默认网关；B 的另一块网卡继续连接 PLC 网络，不要桥接两块网卡。Wi-Fi 可以保留，但不要让它使用同一网段；必要时把直连网卡的跃点设低一些。Windows 防火墙至少允许 B 入站 TCP 32000 和 UDP 32001，来源限定为 A 的 `192.168.50.1`；A 允许对 B 出站 TCP 32000 和 UDP 32001。不要把这两个端口映射到公网。

PLC 的物理 IP 和 AMS Net ID 不能从当前工程可靠推断。源码当前固定使用 PLC AMS Net ID `169.254.119.135.1.1`、ADS 端口 851；`169.254.119.135` 看起来像现场链路地址，但不是可以替代验证的普通 IP。B 上的 ADS Router 必须把该 AMS Net ID 路由到 PLC 的真实 IP，PLC 端也需要回到 B 的 AMS Net ID 路由。若现场 Net ID 不同，先在工程和现场配置中确认，不要只改电脑 IP。

## 第四步：配置 ADS Route

在 B 上打开 TwinCAT Router/AMS 路由工具，新增 PLC 的实际 AMS Net ID 和实际 PLC IP；确认路由状态为可达。在 PLC 侧添加 B 电脑的 AMS Net ID 和 B-PLC 网卡 IP。然后在 B 上用 ADS 诊断工具读取 PLC 851 状态，成功标志是 ADS 通信可打开且 PLC 状态为 RUN。当前 ADS 连接函数中的 “ReadOnly” 只表示不请求切换 PLC 状态，后续控制周期仍可能写入心跳和控制变量，因此不要把它当作纯监视模式。

## 第五步：启动顺序

先给 PLC/控制器上电，确认安全回路、急停和限位状态正常，TwinCAT Runtime 处于 RUN。接着在 B 上确认 ADS Route 和 PLC 851 可读，再从 `B_从端电脑\运行` 启动 `ADS.exe`。控制台应出现远程网关已启动、ADS 通信服务启动以及 PLC 快照正常的提示；若网关未启动，首先检查 `remote.token` 是否存在且与 A 一致。最后在 A 上从 `A_主端电脑\运行` 启动主端，连接地址填 B 的直连网卡 IP。主端成功标志是 TCP 认证完成、状态帧开始刷新、ADS/链路状态可见、两只手柄显示在线；随后申请控制权，确认从端状态允许后再点击开始控制。开始控制前先确认机器人处于准备位置、急停可用、手柄在中立位置。

出现通信或安全故障时，先松开所有点动按钮并按现场急停要求停止动作，再在 A 释放控制权/退出主端，最后在 B 停止 ADS.exe；不要先拔网线或直接杀进程。重新启动时按 PLC、B、A 的顺序执行。

## 第六步：低风险验证

先做不运动的链路检查。B 启动 ADS.exe 后只观察 PLC 状态和状态帧，A 启动主端并连接，但不要申请控制权；成功标志是 TCP/UDP 建链、心跳和状态帧计数增加。随后可在 A 的模拟模式 `--sim` 启动主端，确认窗口、URDF 模型和布局加载；这只验证界面，不验证 PLC。

再做主端到从端的命令检查。申请控制权后先使用停止、归零或零值参数，确认 TCP 命令得到响应；定位臂命令会进入从端既有 ArmManual/ArmCartesian 入口，但当前状态帧协议主要回传血管机器人七轴状态，不要把旧 DSA URDF 模型当成 PLC 定位臂的闭环显示。主端 RobotViewport 当前是独立 DSA URDF 显示控件，隔离检查已验证模型资源、加载、缩放、旋转和状态应用接口，但生产状态链路没有把 PLC 七轴自动转换为该旧模型的九关节状态。因此，离线模型运动通过不等于真实 PLC 驱动模型运动。

真实 PLC 测试必须由熟悉设备的人员执行。先确认软限位、硬限位、停止、急停、通信超时保护均有效，再只发送零位或极小、可逆参数，逐步观察 PLC 状态回传、B 的状态采集、A 的状态显示和 RobotViewport 的实际刷新。若图像不动，按顺序检查 PLC 是否有状态、B 是否读到、B 是否发出状态帧、A 是否收到和解析、单位/轴号是否匹配，以及模型控件是否真正订阅该字段；当前项目中 PLC 七轴状态与旧 DSA URDF 模型并未形成生产闭环，这一点必须单独记录。

## 第七步：常见故障

A 能启动但连接不上 B 时，先在 A 执行 `Test-NetConnection 192.168.50.2 -Port 32000`，再检查 B 防火墙、IP、密钥和 ADS.exe 是否仍在运行。TCP 能通但状态不刷新时，检查 UDP 32001 防火墙和网卡路由。认证失败通常是两端 `remote.token` 内容不同或长度不足。B 网关启动但 ADS 不正常时，检查 TwinCAT Router、PLC 真实 AMS Net ID、路由回程和 851 状态；不要把 TCP 32000/UDP 32001 与 ADS 的 851 逻辑端口混为一谈。手柄离线时只在 A 检查 FLCatheter.dll、手柄驱动和 USB 连接；B 端不应再接入主端手柄。

## 第八步：包内文件说明

`A_主端电脑\运行` 是主端现场目录，`B_从端电脑\运行` 是从端现场目录；两个目录各自有启动脚本、README 和文件清单。`源码备份` 保存本地已有的主端/从端源码、协议、手柄 SDK 头文件/库文件、定位臂源码、Eigen 头文件和 Math4wpf/can4wpf 库源码，便于追溯和重新编译；它不参与运行。当前 Release 构建和主端离线模型检查已完成，但没有连接真实 PLC、ADS Router、手柄或机器人，也没有做带运动的现场试验。
