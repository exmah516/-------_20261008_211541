# 2026年10月13日主端摄像头黑屏验证

1. 本次只处理用户指定的 `A_主端电脑_地址修正版\工程\master\MasterConsole.sln`。最终在该工程的主端窗口中看到监控1真实画面，保存为 `主端窗口.png` 和 `主端窗口-监控1.png`，另保存直接来自解码器的 `camera1-decoded.png`。摄像头地址为192.168.1.64，读取工程现有私有配置，不在测试代码中保存账号或密码。

2. 根因是发布依赖不完整。SDK原始日志显示缺少 `libcrypto-1_1-x64.dll`，RSA密钥生成失败，随后私有同步登录返回29；同目录还缺少配套的 `libssl-1_1-x64.dll` 和 `zlib1.dll`。本次从旧工程 `血管整体项目程序\code\build\Debug\bin\net472` 复制这三个文件，以及播放组件 `SuperRender.dll`、`YUVProcess.dll`，保持与现有HCNetSDK 6.1.9.48配套。此前已补入的HCCore.dll、AudioRender.dll继续保留。已验证七个文件的源文件和Debug/Release输出哈希一致。

3. 最终修改为上述五个Runtime文件、`master/MasterConsole/MasterConsole.csproj`的输出复制规则、`tools/runtime-files.txt`依赖清单，以及`tools/HikCameraCheck`隔离测试。登录仍为原来的4字节BOOL同步封送和LoginMode=0私有协议；没有保留试验性的I1封送、登录模式切换、SetDllDirectory或SetSDKInitCfg。之前的TCP直接渲染修改保留。不能把错误结构体取得的异步句柄当作登录成功；此前试验中产生的这一误判已排除。

4. 验证结果：主解决方案Debug和Release编译通过，0错误，完整编译保留原有CS0414警告。隔离测试直接实例化现有HikCameraView，经过其原有配置、登录、预览和解码路径；Debug解码帧从1增长到28，Release从1增长到27，图像尺寸均为1280×720。只在隔离测试输出目录暂时移走libcrypto DLL后，测试返回失败并复现登录错误29；还原后同一测试恢复通过。原有协议测试30项通过、0项失败，git diff --check通过。未改相机配置、网关、PLC、手柄和机器人控制代码。

5. 重复验证时，在工程目录执行 `dotnet build tools/HikCameraCheck/HikCameraCheck.csproj -c Debug`，再执行 `tools/HikCameraCheck/bin/Debug/net472/HikCameraCheck.exe 1`。测试只打开摄像头控件，正常情况下数秒内自动退出；可在摄像头编号后追加PNG文件路径保存解码截图。日常使用仍打开原解决方案，重新生成并运行主端，点击“监控1”即可放大画面。测试时机器人链路使用--sim，未连接或控制真实机器人；第二路192.168.1.32未连接、返回7，未验证双摄像头实机并行或长时间断线恢复。
