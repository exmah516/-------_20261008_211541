# 摄像头从端内置 TCP 转发验证

采用 ADS.exe 内的 HikCameraRelay 单线程转发，固定监听 192.168.50.2:18000，仅接受 192.168.50.1，向 192.168.1.64:8000 建立连接。摄像头方向同时绑定源地址 192.168.1.96 及该地址对应的 IP_UNICAST_IF，绑定失败不退回其他网口。每条连接每个方向只保留一个 64 KiB 缓冲区，最多八条连接；非阻塞 connect 最长三秒，积压数据三十秒无发送进展则关闭连接。正常空闲的 SDK 控制连接不因无视频字节被误断开。

主程序仅增加包含、服务启动及退出调用，转发不进入运动主循环。ADS.vcxproj 和 filters 已包含新模块。主端 camera1 私有配置及模板改为 192.168.50.2:18000，真实配置的账号、密码、通道、码流及 camera2 保持原样。没有修改主端视频代码、控制协议、PLC 工程或系统网卡/路由/防火墙，也没有新增生产转发脚本。

2026年10月13日，通过现有 build-and-run.ps1 的 -BuildOnly 分别编译 ADS.sln 的 Debug/x64 与 Release/x64，均退出码 0，未启动真实 ADS 主程序或真实运动。

运行现有隔离测试入口 `python 工程/ADS项目/tools/run_ads_diagnostics_test.py hik_camera_relay_test`，退出码 0。测试直接编译真实 hik_camera_relay.cpp，覆盖三条并行 TCP 连接、超过 3 MiB 二进制数据逐字节一致、小接收缓冲和延迟接收、半关闭、重复停止/重启、端口占用、非授权主端、USB 地址缺失时禁止后备出口、摄像头拒绝连接、八连接上限、第九连接拒绝、活跃连接退出小于 1.5 秒及非法地址。测试只使用回环替身，不加载 ADS 或手柄 SDK。

随后用相同 C++ 转发模块连接现场已接在本机的真实摄像头：仅在隔离测试参数中使用监听 127.0.0.1:18000、允许来源 127.0.0.1、USB源地址 192.168.1.100 和目标 192.168.1.64:8000。主端现有编译后的 HikCameraSession 经该转发登录和解码，取得 PASS frames=1->101，size=1280x720。诊断进程结束后释放监听，没有持久修改网络配置。此结果证明新增原生转发模块能传递现有设备的 SDK 登录及视频流，不等同于两台电脑的现场验收。
